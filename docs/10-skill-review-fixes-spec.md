# 技能机制审查修复规格

## 已验证的问题与验收

1. **NOT RUN 重放**：隔离报告中 `Lint` 标为 NOT RUN，但闸门执行了其创建标记文件的命令并返回 proceed。只重放实际 PASS 的命令；NOT RUN 不执行，仍进入缺口清单；没有可重放的 PASS 时不得冒充已有可重放证据。
2. **阶段保护与 force**：阶段 1 未完成时 `--upgrade --stage 2 --force` 返回 0 并覆盖已有 AGENTS.md。阶段 1 始终必须通过；force 仅用于明确覆盖，不再绕过阶段保护，拒绝时不写入。
3. **生成的 init 命令引用**：`node -e "process.exit(0)"` 生成的 init.sh 因展示行语法错误退出 2。展示命令必须安全引用，原命令只执行一次；两个自包含技能各自验证。
4. **空账本目标**：空白 goal 和 attempts 数组被阶段 2 判为有效。缺失、非字符串、空白与占位值均不通过，真实目标通过。
5. **完成报告**：机械判据通过、人工判据未确认时，报告写 COMPLETE 和全部完成。阶段 2 应明确标识机械完成及人工验证待确认，不改变机械 `--require` 退出语义。
6. **基准漂移**：将 main 移到候选 HEAD 后，原始基准到 HEAD 的 diff 包含文件，而 `main...HEAD` 为空。创建现场时记录原始基准 commit；验证与闸门使用同一固定 commit，缺失时停止并恢复证据。

## 执行顺序与验证

每次只修改一个技能或脚本，先增加能在旧实现失败的行为断言，记录失败，再修改并验证；必要的文档与测试随对应单元处理。保持技能独立安装，不跨技能导入；不降低既有断言。最终执行 `bash init.sh` 并记录结果，核对工作树与提交范围。未执行的检查明确标记 NOT RUN。
