# 04 · 安全：护栏、权限、事件响应

本文档定义循环的安全边界。核心原则：**默认关闭，显式开启，触及即停。**

---

## 安全姿态

三条底层假设：

1. **循环会犯错。** 设计目标不是"不犯错"，而是"犯错时代价可控且能被发现"。
2. **权限只能收窄，不能放宽。** 仓库级约束可以比默认更严，不可以更松。
3. **没有显式允许，就是不允许。** 默认拒绝，不是默认放行。

---

## 拒绝列表（Denylist）

未经人工批准，**绝不自动编辑**以下路径：

```
.env
.env.*
**/secrets/**
**/credentials/**
**/*_key*
**/*_secret*
.terraform/**
k8s/production/**
**/migrations/**        # 除非有明确的迁移循环
auth/**
payments/**
billing/**
```

### 强制写入技能

`minimal-fix` 与所有执行类技能必须包含这条原句：

> Do not modify files matching the denylist. Escalate to human with context.

### 命中时的动作

1. **停止编辑。** 不做"顺便的小改动"，不做"只是加个注释"。
2. 在 `STATE.md` 写升级条目，包含：路径、为什么需要改、建议的改法。
3. 通知人工（若配置了连接器）。
4. work item 进入 `escalated`。

**拒绝列表路径的改动由人工合并**，即使 verifier 通过。

---

## 自动合并策略

**默认：不自动合并。**

| 允许 | 不允许 |
|---|---|
| 修正注释/文档中的拼写错误 | 行为变更 |
| 仅自动修复测试文件中的 lint 问题 | 依赖版本升级 |
| 调整导入顺序 | 锁文件变更 |
| 允许列表内 `docs/` 路径的配置 | 任何拒绝列表路径 |

允许列表写入 `loop-auto-merge-allowlist.md`，**必须逐条列出路径**。不接受 `docs/**` 这类宽松模式——那等于把整个文档树变成可自动写入区域。

启用自动合并前必须满足：
- verifier 已连续两周可靠工作
- 允许列表已逐条审计
- 有 kill switch 且已验证可用
- 有运行日志可回溯

---

## 连接器（MCP）最小权限

| 连接器 | 读取 | 写入 | 禁止 |
|---|---|---|---|
| GitHub | issues、PRs、checks | comment、label | 默认不执行 merge |
| Linear / Jira | 团队 issues | comment、status | 不执行 delete |
| Slack | 频道历史 | 仅 post 到 `#loop-escalations` | 不发私信、不 @ 全体 |
| 数据库 | — | — | **禁止循环写入生产环境** |

### 规则

- 使用独立机器人账号与最小权限 token。
- **L1 只用只读连接器。** 建立信任后才扩大范围。
- 权限扩大必须在 `STATE.md` 记录，并有至少两周可靠运行记录作为依据。
- PR 评论中机器人身份必须明确（例如 `🤖 Loop Harness — PR Review Triage`），让人一眼看出哪些是机器写的。

---

## 人工审核关卡（必需，始终）

以下情况必须人工介入，不可由循环决定：

- 安全 / 身份认证 / 授权相关
- 支付 / 计费 / PII 处理
- 基础设施 / Terraform / K8s 生产环境
- 依赖升级（供应链风险）
- 涉及超过 10 个文件的变更
- 对同一事项的第 3 次尝试失败
- 破坏性数据库模式迁移

---

## 机密信息

- **绝不**将 API key、token、凭据粘贴进调度提示词。
- CI 日志可能含机密；triage 技能写入状态文件前**必须脱敏**。
- `STATE.md` 会被提交到仓库，**不得包含任何凭据**。
- `loop-run-log.md` 同样会被提交，错误信息中可能含路径与内部标识，写入前检查。

---

## 偶发失败与测试安全

- **绝不为让 CI 通过而禁用测试、跳过断言、注释掉检查。** 这是最严重的作弊形式。
- 不要在未记录根因时盲目增加超时。
- 隔离 flake 必须有明确工单和人工批准。
- flake 的处理是**分类后隔离**，不是"用代码修复"：

```
同一测试先失败、随后无代码改动重试通过 → 分类为 flake → 加入 Watch，不自动修复
```

## Kill Switch

### 机制

| 层级 | 方式 |
|---|---|
| 单轮 | `loop-pause-all` 标签或 `STATE.md` 标志 → 循环立即退出 |
| 调度层 | 删除调度器 / 禁用 workflow |
| 全局 | 撤销连接器 token |

### 规则

- 循环每轮开始**必须**检查 kill switch。
- 恢复需要人工在 `STATE.md` 中清除标志，然后手动重启调度器。**循环不得自行恢复。**
- kill switch 必须至少演练一次，确认真的能停住。

---

## 事件响应：循环合并了有问题的代码

按顺序执行：

1. **立即暂停所有循环。** 删除调度器或禁用 automations。
2. **还原该合并。**
3. **记录**到 `STATE.md` 与运行日志（含 token 成本、根因、补救）。
4. **收紧 verifier 或缩小范围**，然后才考虑重启。
5. 在 `stories/` 或等价位置写下这次失败——**失败故事比成功故事更有价值**，它记录了系统的真实边界。

**绝不在未找到根因时重启循环。** 否则同一个问题会再次发生。

---

## L3 前运行前安全检查（5 项）

启用无人值守运行前，逐项确认：

- [ ] 技能中已包含拒绝列表
- [ ] 已关闭自动合并，或配置了严格的逐条允许列表
- [ ] 已审计连接器权限范围（确认没有 write 到生产）
- [ ] 模式文档中已记录人工审核关卡
- [ ] 已记录并测试过紧急停止开关

**五项全过才允许 L3。** 任一项缺失，停在 L2。

## 反模式速查

| 反模式 | 为什么危险 | 正确做法 |
|---|---|---|
| 第一天就给 MCP 无限写权限 | 循环能在你不知情时改生产工单、合并 PR | L1 只读，逐步扩大 |
| 没有 kill switch | 出问题时只能看着它跑 | 每轮检查标志，演练一次 |
| 用代码修复间歇性故障 | 掩盖真实问题，把 flake 变成隐藏 bug | 分类 → 隔离 → 升级环境问题 |
| 没有路径允许列表却开启自动合并 | verifier 通过 ≠ 改动安全 | 逐条允许列表 + 拒绝列表 |
| 把凭据放进调度提示词 | 凭据进入日志、状态文件、git 历史 | 只用环境变量或密钥服务 |
| 升级只写进没人读的状态文件 | 等于没升级 | 连接器通知 + 收件箱区 + 超时告警 |

---

## 与 MiMosa 安全约束的一致性

若本框架用于服务端请求场景，额外约束：

- 请求 URL 仅允许 `http`/`https`；发请求前校验 host，拒绝 localhost、环回、私有与保留地址。
- 凭据只从环境变量或密钥服务读取；源码、示例、测试中都不写入可用的凭据字面量。

这两条与上面的机密信息规则一致，属于同一原则在具体场景下的展开。
