# 流程冲突修复 spec

日期：2026-10-27。范围是四个技能当前流程中的实际冲突及其必要的运行时支持；不重设计技能边界、替换验证规则或自动合并。

## 已定位与验证

1. **未合并成果被清理**：在临时 Git 仓库分别创建 `rejected` 和 `escalated` worktree，提交一项未合并改动后执行 `cleanup`。两次均退出 0，目录和分支均消失。根因是 `worktree.mjs` 只对 `merged` 做祖先检查，其他状态直接 `git branch -D`。模板也要求丢弃现场；需同步调整。
2. **发现队列反序、无法移除旧条目**：从已有待办开始，依次写入 P1、P2 后实际顺序为 P2、P1、既有条目。脚本只插入首项之前；对 `--remove` 返回未知参数。技能同时禁止直接编辑并要求移除已关闭条目。
3. **验证完成与合并完成混淆**：循环只允许人工合并，但步骤 7 对所有结果要求勾选或移除 High Priority；`state-commit` 的 `verified` 会清空 Active。静态路径确认缺少等待合并的交接与保留方式。
4. **独立会话交接不完整**：无子智能体时要求只做第 5 步，但未列工作树、基准、提交、报告及结果交接的具体输入。静态检查确认缺少这些契约；未执行真实跨会话测试。
5. **阶段 2 机械与人工完成语义易混淆**：`stageComplete` 排除人工判据，`--require` 因此只判断机械项；技能另外要求两项真实使用证据。现有实现符合机械闸门设计，应明确区分，不应改变退出码冒充人工验证。
6. **发现分类证据不足**：列出的 `gh` 查询无法单独证明 flaky 重试结果、分支保护规则、阻塞评论或故障根因；应按需补充只读证据，未知时不作肯定分类。未连接真实 GitHub 仓库，实时查询为 NOT RUN。

基线：`bash init.sh` 退出 0，864 passed / 0 failed；其测试断言不能替代以上流程复现。

## 修改计划与验收

1. **worktree 脚本**：所有可清理状态都须先证明分支已包含于原 base；否则保留目录、分支与 manifest，退出 2。无新提交的拒绝或升级分支仍可清理；未提交改动仍不可删除。先添加分别覆盖 rejected、escalated、重复清理与无新提交的回退断言，确认旧实现失败，再实现。
2. **worktree 对应技能及模板**：说明未合并成果保留、人工处理后再清理；禁止 `git add -A` 带入无关文件。修改技能和模板时分别验证，确保每次只有一个技能或脚本在变更。
3. **发现写入脚本**：提供明确的末尾写入选项，使新待办按调用顺序追加并保留已有条目顺序；兼容原有默认插入行为。新增按精确 `issue#N` / `pr#N` 来源移除条目的受控入口，只影响指定节与带来源标记的条目。验证重复来源、相似编号、其他节、空节及第三方清洗；旧实现必须在新断言上失败。此策略不声称自动重排已有待办，执行者须按优先级写入新条目。
4. **发现技能**：定义已有条目的去重和关闭状态的精确来源移除；按需取证并将不可证实状态标为未知；保留只读 GitHub 边界。
5. **循环技能**：验证通过但未合并的项标记为等待人工合并，不勾选或移除；独立会话说明输入、输出和交接，且保持审查者与执行者分离。失败与未完成的项保留或升级，不误标完成。
6. **阶段 2 技能**：分别报告机械装配通过与人工使用证据；缺少人工证据如实标记 NOT RUN，不改变 `--require` 的机械判定。

每项先做相关验证再进行下一项，完成后运行 `bash init.sh`；脚本行为的新断言必须在旧实现上失败，在修复后通过。未运行的真实跨会话和 GitHub 测试在结果中注明。
