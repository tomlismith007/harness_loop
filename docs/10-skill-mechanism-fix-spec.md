# 技能机制修复 spec

## 定位与结论

1. 行为改动的回退测试：隔离样例中报告为 NOT RUN、参数为 pass，闸门返回 proceed。对 behavior，闸门应要求报告恰有一条 Red check: PASS，且调用参数必须为 pass。
2. 状态事务：代码路径显示 STATE 与运行日志成功后，锁终态写入可能失败；原指令误称所有失败均回滚。将锁终态纳入同一回滚范围，并验证注入失败后的恢复。
3. 账本：技能指示验证通过即 success，但闸门仍可能拒绝；调整为最终闸门通过后记录成功，失败路径按实际结果入账，明确尝试计数的时序。
4. Watch：发现技能既要求写 Watch，又禁止非待办写入；改为最终报告 Watch，不写本地状态。
5. 完成标准截断：隔离样例中长条目写入成功而完成标准丢失。对不可信条目拒绝超过上限的输入，要求调用者缩短并重试，不猜测标准语义。
6. 执行边界：阶段报告会运行目标 init.sh；证据重放会执行报告中的 shell 命令。明确在执行前检查内容、授权和副作用；不引入额外授权流程。

## 执行与验收

- 按脚本或技能逐个实施并验证；行为变更先增加能在旧代码失败的回归断言。
- 覆盖回退状态缺失、NOT RUN 与 pass 冲突；覆盖锁终态写入失败时状态、日志与锁一致回滚；覆盖超长发现条目被拒且文件不变。
- 修正文案并验证命令与流程仍一致；完成后运行 `bash init.sh`，记录结果并检查仓库状态。
- 事务不承诺断电或进程被强制终止时的跨文件原子性；发生这类中断仍需检查备份和锁。
